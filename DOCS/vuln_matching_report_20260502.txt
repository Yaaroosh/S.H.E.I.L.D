[1] Prompt Injection (LLM01)
    Report Finding: None detected
    Explanation: 
    This is a logic/API flaw requiring manual testing of the /api/chat endpoint.
    SAST/DAST scanners cannot automatically detect prompt injection vulnerabilities
    without specific payload knowledge. The vulnerability involves the "role" 
    parameter being injected into the System Prompt without validation in 
    routes/chatRoute.js.

[2] Broken Object Level Authorization (API3:2023) - Admin User Creation
    Report Finding: None detected
    Explanation:
    Business logic vulnerability: during user registration, the isAdmin parameter
    is copied directly from user input without validation. SAST/DAST cannot 
    detect parameter-level authorization bypasses without explicit business logic
    rules defined. The flaw is in services/userService.js createUser() function.

[3] Insecure Design (A04:2021) - Negative Cart Balance
    Report Finding: None detected
    Explanation:
    Business logic vulnerability in services/OrderService.js removeCartItem().
    The function decrements item quantity without checking if it's already zero,
    allowing negative balances. Not detectable by automated scanners as it 
    requires understanding of business constraints.

[4] Broken Function Level Authorization (API5:2023) - Open Orders
    Report Finding: None detected
    Explanation:
    Authorization bypass at endpoint level: GET /admin/orders lacks the isAdmin
    middleware check that protects other admin endpoints. ZAP/CodeQL cannot 
    detect missing middleware without explicit endpoint authorization rules 
    defined. The flaw is in routes/adminRoutes.js.

[5] Stored XSS (A03:2021-Injection)
    Report Finding: [101-120] - 20 Cross-Site Scripting (XSS) instances
    Explanation:
    S.H.E.I.L.D detected 20 XSS instances in the scan. The DOCX specifically 
    describes Stored XSS in the /manage-users.js file where user data is appended
    to DOM without sanitization. The vulnerability allows injecting scripts via
    registration fields (PhoneNumber, FirstName, LastName). When an admin views
    the user list, the JavaScript executes under admin context.

[6] Broken Object Level Authorization (API1:2023) - Change Password
    Report Finding: None detected
    Explanation:
    Business logic vulnerability in services/userService.js updatePassword().
    The function accepts an email parameter and changes its password without
    verifying the requesting user is the owner of that email. No current password
    check. Not detectable by scanners without explicit endpoint authorization 
    logic defined.

[7] Server-Side Template Injection (SSTI) (A03:2021-Injection)
    Report Finding: [935] - js/code-injection (CRITICAL)
    Explanation:
    CodeQL detected CRITICAL severity code-injection in controllers/successController.js.
    This matches the DOCX finding of SSTI via ejs.render(). The vulnerability occurs
    when the "controller" parameter from a POST to /successPage is passed directly to
    ejs.render() without validation, allowing arbitrary JavaScript execution on the
    server side (Node.js context).
